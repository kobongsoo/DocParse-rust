DocParse-rust · 사용 안내 · 2026-11-16 · 라이브러리 0.1.1 (ABI 1)

문서 파서 DLL 빌드하고 CLI 로 시험하기

이 저장소는 문서(pdf · docx · xlsx · pptx · hwpx · hwp · html · 텍스트 …)에서 본문 텍스트를 뽑고 압축(zip · 7z · rar …)을 펼치는 라이브러리 docparse.dll 을 만든다. 이 안내를 위에서부터 따라 하면 DLL 을 빌드하고, 함께 만들어지는 시험 프로그램 dp.exe 로 문서를 직접 넣어 결과를 볼 수 있다. 명령은 모두 PowerShell 기준이고, 저장소 폴더 D:\Project\DocParse-rust 에서 실행한다.

이름 정리 — 라이브러리는 Windows docparse.dll · Linux libdocparse.so, 시험 프로그램은 Windows dp.exe · Linux dp 다. 크레이트 이름(docparse-ffi · docparse-cli)과 파일 이름이 다르니 헷갈리지 않게 주의한다.

1전체 흐름 한눈에

STEP 1준비Rust 설치 · 저장소 폴더로 이동
STEP 2빌드cargo build --release 한 줄
STEP 3옆에 두기pdfium.dll 하나 복사
STEP 4시험dp.exe extract 문서 로 본문 보기

DLL(docparse.dll)은 다른 프로그램이 불러 쓰는 부품이라 혼자서는 실행되지 않는다. 그래서 시험 프로그램 dp.exe 를 함께 빌드한다. dp.exe 는 DLL 의 C 진입점 소스 (crates\docparse-ffi\src\lib.rs)를 그대로 넣어 같은 함수(docparse_extract 등)로 문서를 읽는다. 옵션 JSON 을 만들고 · 결과 JSON 을 받고 · docparse_free 로 돌려주는 과정까지 같으므로, dp.exe 로 본 결과가 곧 DLL 의 결과다.

3빌드하기

PowerShell 을 열고 저장소 폴더로 간다.

cd D:\Project\DocParse-rust

전부 빌드한다(DLL + 시험 프로그램). 처음에는 의존 라이브러리를 받아 몇 분 걸리고(이 PC 에서 약 5분), 다음부터는 바뀐 부분만 빌드한다.

cargo build --release
끝에 이렇게 나오면 성공

만들어지는 파일

파일무엇

target\release\docparse.dll.libC/C++ 에서 링크할 때 쓰는 가져오기 라이브러리(배포 묶음에서는 lib\docparse.lib 로 이름을 바꿔 넣는다)

4실행 파일 옆에 둘 것

PDF 를 읽으려면 pdfium.dll 이 필요하다. 라이브러리는 DLL(또는 dp.exe)이 있는 폴더 → 실행 파일 폴더 → 시스템 순서로 찾는다. 그래서 빌드 결과 폴더에 한 번 복사해 둔다(scripts\win-build.sh 를 돌렸다면 이미 복사돼 있다).

Copy-Item .\third_party\pdfium\windows-x64\pdfium.dll .\target\release\
target\release\ ├─ docparse.dll ← 빌드 결과 ├─ dp.exe ← 빌드 결과 └─ pdfium.dll ← 복사
pdfium 을 다른 곳에 두었다면 복사 대신 --pdfium 경로 옵션으로 알려 줄 수 있다(옵션 JSON 의 pdfium_lib). pdfium 이 없어도 PDF 가 아닌 문서는 그대로 읽힌다.

6문서 하나 추출 (extract)

가장 기본 명령이다. 문서를 넣으면 정제된 본문이 화면에 나오고, 마지막에 요약 한 줄([dp] …)이 붙는다.

.\target\release\dp.exe extract .\tests\samples\보고서_예시.docx
화면(앞부분)
문서 파서 시험용 보고서
1. 개요
이 문서는 구조화 문서 파서를 시험하려고 지어낸 예시 문서다.
제목, 문단, 목록, 표, 머리글과 꼬리글이 모두 들어 있다.
2. 처리 절차
…
[dp] fmt=docx engine=docx chars=333 4ms
요약 줄뜻
fmt감지한 형식
engine실제로 본문을 뽑은 추출기(폴백했으면 감지와 다를 수 있다. 사이냅이면 snf)
chars본문 글자 수(바이트가 아니라 글자)
ms걸린 시간
partial=상한 때문에 앞부분만 읽었을 때만 나온다(8장)
layout= · 판정=PDF 일 때 쪽 수 · 그림만 있는 쪽 수, 그리고 스캔 PDF 판정(docparse_scan_pdf_verdict)
요약 줄은 표준 오류로 나가므로, 본문만 파일로 받고 싶으면 > 로 돌려도 요약 줄은 섞이지 않는다. 다만 PowerShell 의 > 는 파일을 UTF-16 으로 쓰므로, 본문 저장은 아래 --out 을 쓴다(UTF-8 그대로 쓴다).
.\target\release\dp.exe extract .\tests\samples\보고서_예시.docx --out .\work\result.txt
화면
[dp] 저장: .\work\result.txt
[dp] fmt=docx engine=docx chars=333 4ms

경로에 띄어쓰기가 있으면 꼭 따옴표로 감싼다. 한글 경로도 그대로 된다. work\ 는 git 에 올라가지 않는 작업 폴더다.

7결과 JSON 읽는 법

--json 을 붙이면 본문 대신 라이브러리가 돌려준 결과 JSON 전체가 나온다. 다른 프로그램이 DLL 에서 받는 것과 똑같다.

.\target\release\dp.exe extract .\tests\samples\글자층_예시.pdf --json
화면
{
  "engine": "pdf",
  "fmt": "pdf",
  "layout": {
    "pages": 2,
    "scan_pages": 0
  },
  "partial": null,
  "text": "문서 파서 시험용 PDF\n이 쪽은 글자층이 있는 PDF 의 첫째 쪽이다.\n…"
}
[dp] fmt=pdf engine=pdf chars=131 32ms layout={"pages":2,"scan_pages":0}
필드뜻
text본문(UTF-8). 기본은 6단계 정제를 거친 것, --raw 면 정제 전 원시 텍스트
fmt감지한(또는 --fmt 로 정한) 형식
engine실제로 뽑은 추출기 이름
partialnull = 다 읽음. 아니면 {"reason","unit","read","total"} — 예: 3000쪽 상한에서 멈춘 PDF
layoutPDF 만 — pages(읽은 쪽) · scan_pages(글자 없이 그림만 있는 쪽)

실패하면 같은 자리에 {"error": {"kind", "message", …}} 가 온다. kind 는 size_limit(크기 상한) · unsupported(지원 안 함) · failed(깨진 파일 · 암호 등) · arg(옵션 오류) · panic(라이브러리 버그) 중 하나다.

8옵션 바꿔 보기 (정제 · 상한 · 로그)

정제 끄기 (--raw)

기본 본문은 공백 · 빈 줄 · 줄 끝을 다듬은 것이다. 추출기가 뽑은 그대로를 보려면 --raw(옵션 JSON "clean": false).

.\target\release\dp.exe extract .\tests\samples\웹문서_예시.html --raw

상한 바꾸기 (--limit 키=값)

크기 · 쪽 수 · 시간 상한을 바꿔 볼 수 있다. 값에 none 을 주면 그 상한을 없앤다. 여러 번 써도 된다.

9압축 · 정제 · 상한만 (expand · clean · check)

압축 펼치기 (expand)

압축 파일을 --tmp 폴더에 풀고, 추출할 작업 목록을 돌려준다(docparse_expand). 압축 안의 압축도 펼친다(기본 3단계). 압축이 아닌 파일을 같이 넣으면 그대로 목록에 들어간다.

.\target\release\dp.exe expand .\tests\samples\묶음_예시.zip --tmp .\work\풀기
화면(요점)
{
  "jobs": [
    { "label": "./tests/samples/묶음_예시.zip/보고서_예시.docx",
      "origin": "./tests/samples/묶음_예시.zip", "src": ".\\work\\풀기\\a1" },
    { "label": "./tests/samples/묶음_예시.zip/문서_예시.md", … "src": ".\\work\\풀기\\a2" },
    { "label": "./tests/samples/묶음_예시.zip/안쪽_압축.zip/안쪽/평문_예시.txt", … "src": ".\\work\\풀기\\a4" }

src 는 풀린 실제 파일(이름에 확장자가 없다 — 형식은 내용으로 감지한다), label 은 사람이 읽는 원래 경로다. 풀린 파일은 바로 extract 할 수 있다: .\target\release\dp.exe extract .\work\풀기\a1. 상한은 --max-depth N · --max-bytes N · --max-members N(none = 없음). --tmp 폴더는 dp 가 지우지 않으니 다 보면 직접 지운다.

정제만 (clean)

UTF-8 텍스트 파일을 읽어 extract 와 같은 6단계 정제만 한다(docparse_clean_text). 정제 전 본문을 --raw 로 저장해 두고 정제해 보면, extract 의 기본 결과와 같아진다(두 줄을 차례로):

.\target\release\dp.exe extract .\tests\samples\웹문서_예시.html --raw --out .\work\raw.txt
.\target\release\dp.exe clean .\work\raw.txt
화면 — 108 글자 원시 텍스트가 91 글자로(앞쪽 빈 줄 · 연달은 빈 줄 · 줄 끝 공백 정리). extract 기본 결과의 chars=91 과 같다

}

10여러 문서 한꺼번에 (dump · compare)

① 목록 만들기

메모장으로 한 줄에 문서 경로 하나씩 적어 .txt 로 저장한다(UTF-8). 빈 줄과 # 로 시작하는 줄은 건너뛴다. 상대 경로는 dp.exe 를 실행한 폴더 기준이다. 저장소에는 시험 문서 10건 목록 tests\samples.txt 가 이미 있다. 목록 대신 폴더를 주면 안의 파일(하위 폴더 포함)을 이름 순으로 모두 읽는다.

실제 업무 문서로 시험하려면 tests\private\(git 에 올라가지 않음)에 문서와 목록을 두고 쓴다. hwp · hwpx · doc · xls · ppt 는 공개 시험 문서가 없으니 이 폴더에 넣어 시험한다.

② dump — 문서마다 본문 저장

.\target\release\dp.exe dump .\tests\samples.txt .\work\out_a
화면 — 문서마다 걸린 시간 · 형식
[1/10]     38ms pdf   글자층_예시.pdf
[2/10]      1ms 실패(4) 묶음_예시.zip — 지원하지 않는 포맷(감지=zip)

[4/10]      6ms pptx  발표_예시.pptx
[5/10]      3ms docx  보고서_예시.docx
[6/10]      3ms pdf   스캔_예시.pdf
[7/10]      0ms 실패(4) 아이콘_작음.png — 지원하지 않는 포맷(감지=image)
[8/10]      2ms html  웹문서_예시.html

끝 — 성공 8 · 실패 2 · 0.1초 → .\work\out_a\index.json
work\out_a\ ├─ index.json ← 번호 ↔ 원래 경로 · rc · fmt · engine · chars · ms · partial · layout · err ├─ 0000\글자층_예시.pdf.txt ← 목록 첫 줄의 본문 ├─ 0002\문서_예시.md.txt └─ … (실패한 0001 · 0006 은 폴더가 없다)

실패한 문서는 .txt 가 만들어지지 않는다. index.json 에서 "rc" 가 0 이 아닌 줄과 "err"(사유)를 확인한다. dump 는 문서별 실패가 있어도 끝까지 돌고 종료 코드 0 을 낸다. extract 의 옵션(--raw · --limit · --engine …)을 그대로 붙일 수 있다.

③ compare — 두 결과 비교

코드를 고친 뒤 본문이 달라졌는지 볼 때 쓴다. 고치기 전 dump 를 기준으로 두고, 고친 뒤 다시 dump 해서 비교한다. 여기서는 정제를 끈 결과와 비교해 본다:

.\target\release\dp.exe dump .\tests\samples.txt .\work\out_b --raw
.\target\release\dp.exe compare .\work\out_a .\work\out_b
화면 — 무엇이 어디서 달라졌는지 첫 차이를 보여 준다(⏎ = 줄바꿈)
다름  0000 글자층_예시.pdf — 글자 13 에서 갈림 (길이 131 → 138): «파서 시험용 PDF⏎이 쪽은 글자층이 있는 PDF 의 » ≠ «파서 시험용 PDF⏎이 쪽은 글자층이 있는 PDF 의»
다름  0002 문서_예시.md — 글자 136 에서 갈림 (길이 136 → 137): « 조각 예시⏎```» ≠ « 조각 예시⏎```⏎»
…
다름  0009 평문_예시.txt — 글자 24 에서 갈림 (길이 24 → 25): «째 줄	탭 구분	값» ≠ «째 줄	탭 구분	값⏎»
같음 2 · 다름 8 · 새 쪽에 없음 0 (기준 10건)
  • 첫 번째 폴더가 기준이다. 번호마다 먼저 rc · fmt · engine 을 견주고(다르면 그것을 이유로 보여 준다), 둘 다 성공이면 본문이 글자 하나까지 같은지 본다.
  • 없음 = 기준에는 있는데 새 쪽 index.json 에 그 번호가 없음(목록이 짧아졌을 때).
  • 걸린 시간(ms)은 비교하지 않는다.
  • 모두 같으면 같음 N · 다름 0 · 새 쪽에 없음 0 이 나오고 종료 코드 0, 아니면 1.
결과 바뀜 확인 — CHANGELOG.md 는 본문이 바뀌는 수정에 "결과 바뀜"을 적는다. 고치기 전 · 후 dump 를 compare 해서 다름 0 이면 "결과 바뀜 없음", 아니면 달라진 문서를 확인하고 CHANGELOG 에 적는다.

12종료 코드와 오류

실패하면 화면에 실패(코드 이름): 사유 가 나온다. extract · check · detect · expand · clean 의 종료 코드는 라이브러리 상태 코드 그대로다 (docparse.h 의 dp_status). 그래서 배치 파일에서 $LASTEXITCODE 로 바로 가를 수 있다.

코드이름뜻 · 할 일
0DP_OK성공 본문이 비어 있어도 성공일 수 있다 — 스캔 PDF
1DP_ERR_ARG잘못된 인자 · 옵션(예: --engine synap_only 인데 --synap-exe 없음). dp 자체의 사용법 오류도 1 — 철자 확인
2DP_ERR_NOT_FOUND파일 없음 — 경로 · 따옴표 확인
3DP_ERR_SIZE_LIMIT크기 상한 초과 — 깨진 파일이 아니다. 필요하면 --limit 로 올린다
4DP_ERR_UNSUPPORTED지원하지 않는 형식(그림 · zip · 알 수 없는 바이너리)
5DP_ERR_FAILED읽을 수 없는 문서(깨진 파일 · 암호 걸린 문서 등). PDF 가 전부 5 면 pdfium 위치부터 확인(14장)
99DP_ERR_PANIC라이브러리 안 오류(프로그램은 죽지 않음) — 그 문서를 알려 주면 고친다

나머지: compare 는 모두 같으면 0 · 다르면 1, dump 는 항상 0(문서별 결과는 index.json), version 은 ABI 가 1 이 아니면 1.
