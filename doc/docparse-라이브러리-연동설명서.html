요약

docparse 는 문서 → 본문 텍스트를 뽑는 공유 라이브러리(Windows docparse.dll, Linux libdocparse.so)다. 함수 11개를 C 모양으로 내놓고 옵션과 결과는 UTF-8 JSON 으로 주고받는다. 그래서 C 를 부를 수 있는 언어라면 어디서나 쓸 수 있다. 배포 묶음의 lib/ 두 파일은 어느 언어든 항상 가져가고, 언어에 맞는 폴더 하나(python/·rust/·java/·php/·include/+c/)를 더한다.

배포 묶음 구성

DocParse-rust 저장소에서 scripts/win-build.sh·scripts/linux-build.sh 로 만들면 dist/docparse-<버전>-windows-x64.zip · …-linux-x64.tgz 가 나온다. 푼 모양은 아래와 같다.

│  ├─ docparse.dll        ← 본체 (Linux: libdocparse.so)

│  └─ docparse.lib        ← Windows 전용. C/C++ 가 빌드할 때 링크하는 '가져오기 라이브러리'

docparse.lib 는 정적 라이브러리가 아니다

MSVC 가 DLL 을 만들 때 함께 내는 가져오기 라이브러리(import library)다. 안에 코드가 없고 'docparse.dll 의 이 함수를 쓴다'는 목록만 있다. 그래서 C/C++ 프로그램을 링크할 때만 쓰고, 실행할 때는 여전히 docparse.dll · pdfium.dll 이 옆에 있어야 한다. Linux 는 .so 를 바로 링크하므로 이 파일이 없다.

모든 언어에 공통인 규칙

2-1. 라이브러리 두 파일은 같은 폴더에

docparse 는 자기 파일이 있는 폴더에서 pdfium 을 먼저 찾고, 없으면 실행파일 폴더 → 시스템 경로 순으로 찾는다. 그래서 docparse.dll 과 pdfium.dll 을 한 폴더에 두기만 하면 Python(python.exe)·Java(java.exe)·PHP(php.exe)처럼 실행파일이 다른 곳에 있어도 잘 찾는다. pdfium 을 못 찾으면 다른 형식은 그대로 되고 PDF 만 failed 로 실패한다. 옵션 "pdfium_lib" 으로 위치를 직접 줄 수도 있다.

2-2. 문자열은 전부 UTF-8

경로·옵션·결과 모두 널 종료 UTF-8 이다. Python·Rust·Java·PHP 감싸개는 알아서 맞춰 준다. C 로 Windows 프로그램을 짤 때만 조심해야 한다. main(argc, argv) 의 argv 는 CP949 로 들어오므로 그대로 넘기면 한글 경로가 DP_ERR_ARG 로 실패한다(§6-3).

2-3. 받은 문자열은 docparse_free 로 돌려준다

char** out 으로 받은 결과는 성공이든 실패든 docparse_free(out) 로 해제한다. C 의 free() 는 쓰면 안 된다(할당기가 다르다). docparse_version()·docparse_detect 의 형식 이름처럼 const char* 로 받는 것은 고정 문자열이라 해제하지 않는다. 감싸개들은 이 일을 대신 해 준다.

2-5. 옵션 JSON — 빠진 키는 기본값

옵션은 파일이 아니라 인자

옵션은 설정 파일이 아니라 함수를 부를 때마다 넘기는 JSON 문자열 인자다(예: docparse_extract(path, opts_json, &out) 의 두 번째 인자). 라이브러리는 설정 파일이나 환경변수를 읽지 않는다. 그래서 호출마다 다르게 줄 수 있고, 바꿀 키만 넣으면 나머지는 기본값이다. NULL(또는 빈 문자열)이면 전부 기본값. 넘기는 예시는 아래 §2-5 끝에 있다.

docparse_extract · docparse_check_size 옵션{
  "clean": true,                    // false = 정제 전 원시 텍스트
  "engine": "builtin",              // "builtin" | "synap_fallback" | "synap_only"
  "synap_exe": null,                // engine 이 synap_* 일 때 snf_exe 경로
  "pdfium_lib": null,               // null = docparse 폴더 → 실행파일 폴더 → 시스템
  "label": null,                    // 로그에 적을 문서 이름
  "fmt": null,                      // 주면 감지를 건너뛰고 그 형식으로
  "extra_text": true,               // (0.2.0~) 본문 밖 글도 읽기 — PDF 글상자 주석 · 서식 칸 값,
                                    //   docx 메모, docx/pptx SmartArt. false = 0.1.x 와 같은 본문
  "limits": {
    "parser_timeout_secs": 60,      // 문서 하나 시간 상한
    "max_pdf_pages": 3000,          // PDF 쪽수 상한(넘으면 앞부분만 → partial)
    "max_file_bytes": 104857600,    // 파일 크기 상한(100MB)
    "max_file_bytes_text": 104857600,
    "snf_timeout_secs": 60,
    "min_text_len": 20
  }
}
// 상한: 키가 없으면 기본값, null 이나 0 이하면 '상한 없음'

각 키의 뜻은 아래와 같다.

키형식기본값설명
cleanbooltruetrue 면 뽑은 본문을 6단계로 정제한다: ① 한글 자모를 완성형(NFC)으로 통일 ② 페이지 표식 줄 제거 ③ 제어문자 제거(탭·개행은 남김) ④ CR+LF·CR 을 LF 로 통일 ⑤ 줄 안 연속 공백(탭 포함)을 하나로, 줄 끝 공백 제거 ⑥ 빈 줄 3줄 이상을 2줄로. 양끝 공백도 지운다. false 면 파서가 뽑은 원시 텍스트 그대로다. Python 감싸개만 기본이 False(아래 상자).
engine문자열"builtin""builtin": 자체 파서만 쓴다.
"synap_fallback": 자체 파서로 먼저 읽고, 실패·빈 결과·짧은 결과(공백 뺀 글자 수가 min_text_len 미만)면 사이냅으로 다시 읽는다. 자체 파서가 없는 형식은 처음부터 사이냅.
"synap_only": 모든 문서를 사이냅으로만 읽는다.
모르는 값이면 DP_ERR_ARG.
synap_exe문자열(경로)null사이냅 snf_exe 실행파일 경로. engine 이 synap_* 일 때 반드시 줘야 한다(없으면 DP_ERR_ARG). builtin 이면 무시.
pdfium_lib문자열(경로)nullpdfium 라이브러리 파일 경로. null 이면 docparse 라이브러리가 있는 폴더 → 실행파일 폴더 → 시스템 경로 순으로 찾는다. 못 찾으면 PDF 만 failed.
label문자열null로그 한 줄 안에서 경로 대신 표시할 문서 이름이다. 로그 파일 이름이 아니다(docparse 는 로그 파일을 쓰지 않고 docparse_set_logger 콜백에 줄만 넘긴다). 결과(본문)에는 영향이 없다.
null 이면 파싱한 파일 경로가 그대로 들어가므로 보통은 비워 둔다. 압축에서 풀린 문서만 실제 경로가 C:\Temp\docparse-…\a1 같은 임시 이름이라 무슨 문서인지 알 수 없으므로, expand 결과의 jobs[].label(예: "자료.zip/test.hwp")을 그대로 넘긴다.
fmt문자열null형식을 직접 정한다. 주면 내용 감지를 건너뛰고 그 파서로 읽는다. 값은 docparse_detect 와 같은 철자(pdf · hwp · hwpx · doc · docx · xls · xlsx · ppt · pptx · html · text 등)이고, 모르는 이름이면 DP_ERR_ARG. 보통은 비워 두고 감지에 맡긴다. docparse_check_size 에서는 이 키 대신 함수의 fmt 인자를 쓴다.
limits객체아래 표크기·시간·분량 상한 묶음. 키를 빼면 그 상한만 기본값이다.
limits 의 키단위기본값설명0 이하·null 이면
parser_timeout_secs초(소수 가능)60문서 하나를 읽는 시간 상한. PDF 쪽·HWPX 구역·PPTX 슬라이드·XLSX 시트를 도는 동안 확인하고, 넘으면 거기까지 읽은 앞부분만 돌려준다(partial 에 표시).시간 상한 없음
max_pdf_pages쪽3000PDF 를 읽을 최대 쪽수. 넘으면 앞에서 그만큼만 읽고 partial 에 "페이지 상한(3000p)" 이 남는다.쪽수 상한 없음
max_file_bytes바이트104857600(100MB)읽기 전에 파일 크기를 본다. 텍스트·HTML 이 아닌 모든 형식에 적용된다. 넘으면 열지도 않고 DP_ERR_SIZE_LIMIT(3).크기 상한 없음
max_file_bytes_text바이트104857600(100MB)텍스트·HTML 형식에만 적용되는 크기 상한. 텍스트는 바이트 수가 곧 본문 글자 수라 따로 둔다. 걸리면 결과의 text_kind 가 true.크기 상한 없음
snf_timeout_secs초60사이냅 snf_exe 한 건의 제한 시간. engine 이 builtin 이면 쓰지 않는다.기본값 60 을 쓴다(상한 없음이 없다)
min_text_len글자(공백 제외)20synap_fallback 에서 '짧은 결과' 기준. 자체 파서 결과가 이보다 짧으면 사이냅으로 다시 읽어 보고, 사이냅도 못 읽으면 짧은 결과를 그대로 쓴다. 상한이 아니라 판정 기준이다.0 이면 짧은 결과로 보지 않음. null·음수는 기본값 20
값 규칙

옵션 JSON 자체를 NULL 로 넘기면 전부 기본값이다. 모르는 키는 무시하므로 새 판에 생긴 옵션을 옛 라이브러리에 넘겨도 깨지지 않는다. 상한 키는 빼면 기본값, null·0·음수면 상한 없음이다(snf_timeout_secs·min_text_len 은 예외, 위 표). 주의: 상한 키(parser_timeout_secs · max_pdf_pages · max_file_bytes · max_file_bytes_text)에 숫자가 아닌 값(예: "100" 문자열)을 넣으면 상한 없음이 된다. 나머지 키는 형식이 틀리면 기본값을 쓴다. 옵션이 JSON 객체가 아니거나 깨졌으면 DP_ERR_ARG.

옵션 넘기는 예시 — 같은 설정(정제함 · PDF 500쪽까지 · 파서 시간 30초)을 언어별로 넘기면 아래와 같다. 감싸개를 쓰면 JSON 을 직접 만들 필요 없이 그 언어의 보통 값으로 넘기고, 감싸개가 JSON 으로 바꿔 준다.

C / C++ — JSON 문자열을 그대로char* out = NULL;
/* 바꿀 키만 넣는다 */
int code = docparse_extract("보고서.pdf",
    "{\"clean\":true,\"limits\":{\"max_pdf_pages\":500,\"parser_timeout_secs\":30}}", &out);
docparse_free(out);

/* NULL 이면 전부 기본값 */
code = docparse_extract("보고서.hwp", NULL, &out);
docparse_free(out);

/* 크기 검사도 같은 모양의 옵션(limits 만 본다) */
code = docparse_check_size("큰파일.pdf", NULL, "{\"limits\":{\"max_file_bytes\":52428800}}", &out);
docparse_free(out);
Python — 키워드 인자 (감싸개가 JSON 으로 바꿈. limits 의 키도 평평하게: parser_timeout · max_pdf_pages · max_file_bytes …)r = docparse.extract("보고서.pdf", clean=True, max_pdf_pages=500, parser_timeout=30)
r = docparse.extract("보고서.hwp")                       # 아무것도 안 주면 기본값(단 clean=False)
r = docparse.extract(src, clean=True, label=label)      # 압축에서 풀린 문서: label 로 원래 이름
r = docparse.extract("x.pdf", engine="synap_fallback", synap_exe=r"C:\synap\snf_exe.exe")
Rust — serde_json 의 json! 매크로use serde_json::json;
let r = dp.extract(Path::new("보고서.pdf"),
                   &json!({"clean": true, "limits": {"max_pdf_pages": 500, "parser_timeout_secs": 30}}))?;
let r = dp.extract(Path::new("보고서.hwp"), &json!({}))?;     // 빈 객체 = 전부 기본값
Java — JSON 문자열 (문자열 안의 " 는 \" 로)DocParse.Extracted r = dp.extract("보고서.pdf",
        "{\"clean\":true,\"limits\":{\"max_pdf_pages\":500,\"parser_timeout_secs\":30}}");
DocParse.Extracted d = dp.extract("보고서.hwp");                 // 옵션 없음 = 전부 기본값

// Jackson 을 쓰는 프로젝트라면 Map 으로 만들어 문자열로 바꿔도 된다
Map<String, Object> limits = new HashMap<>();
limits.put("max_pdf_pages", 500);
Map<String, Object> opts = new HashMap<>();
opts.put("clean", true);
opts.put("limits", limits);
DocParse.Extracted j = dp.extract("보고서.pdf", new ObjectMapper().writeValueAsString(opts));
PHP — 연관 배열 (감싸개가 json_encode)$r = $dp->extract('보고서.pdf', ['clean' => true, 'limits' => ['max_pdf_pages' => 500, 'parser_timeout_secs' => 30]]);
$r = $dp->extract('보고서.hwp');                                // null = 전부 기본값

설정 파일로 관리하고 싶다면 그 일은 부르는 프로그램이 한다. 자기 설정(파일·명령줄 인자·환경변수)을 읽어 옵션을 만들어 넘기면 된다. 옵션 JSON 과 같은 모양의 파일을 두었다면 내용을 읽어 그대로 넘겨도 된다. MpowerClassify 는 명령줄 인자(--max-pdf-pages·--parser-timeout 등)를 읽어 매 호출마다 옵션을 만든다.

docparse-opts.json (예 — 이름·위치는 프로그램 마음대로){ "clean": true, "limits": { "max_pdf_pages": 500, "parser_timeout_secs": 30 } }
설정 파일을 읽어 넘기기opts = open("docparse-opts.json", encoding="utf-8").read()     # 문자열 그대로
# C: docparse_extract(path, opts, &out) / Java: dp.extract(path, opts) / Rust: serde_json::from_str(&opts)?
Python 만 기본이 다르다

C·Rust·Java·PHP 는 clean 을 빼면 라이브러리 기본값(true)이다. Python 감싸개의 extract(clean=False) 는 예전 PyO3 모듈과 맞추려고 기본이 False 다. 정제된 본문이 필요하면 Python 에서는 꼭 clean=True 를 준다.

실패: { "error": { "kind": "size_limit"|"unsupported"|"failed"|"arg"|"panic",
                   "message": "사람이 읽는 사유", ...,
                   "layout": {"pages":2,"scan_pages":2} } }   // (0.2.0~) failed 이고 PDF 쪽을 잰 뒤일 때만

성공했을 때(반환 코드 0) 최상위 키:

키형식설명
text문자열뽑은 본문. clean 이 true 면 정제한 뒤다. 본문이 없는 문서(빈 파일 등)는 빈 문자열일 수 있다.
engine문자열실제로 본문을 뽑은 파서 이름. 자체 파서면 형식 이름("docx"·"pdf"·"hwp" …), 사이냅이 읽었으면 "snf". synap_fallback 에서 fmt 와 engine 이 다르면 폴백이 일어난 것이다.
fmt문자열내용으로 감지한 형식(옵션 fmt 를 줬으면 그 값). pdf · hwp · hwpx · doc · docx · xls · xlsx · ppt · pptx · html · text.
partial객체 | null상한에 걸려 앞부분만 읽었을 때만 객체, 끝까지 읽었으면 null. 아래 표.
layout객체 | nullPDF 일 때만 객체, 그 밖의 형식은 null. 아래 표.

partial · layout 안의 키:

안의 키형식설명
partial.reason문자열멈춘 이유. "시간 상한" 또는 "페이지 상한(3000p)".
partial.unit문자열센 단위. "pages"(PDF 쪽) · "parts"(HWPX 구역·PPTX 슬라이드) · "sheets"(XLSX 시트).
partial.read정수실제로 읽은 개수.
partial.total정수문서 전체 개수. read/total 로 얼마나 읽었는지 알 수 있다.
layout.pages정수읽은 PDF 쪽수(쪽수 상한에 걸렸으면 읽은 만큼).
layout.scan_pages정수그중 글자 없이 그림만 든 쪽 수. docparse_scan_pdf_verdict(pages, scan_pages, 본문 글자 수) 에 넘겨 스캔 문서인지 가린다.

실패했을 때(반환 코드 0 이 아님)는 최상위에 error 하나만 있다:

error 안의 키언제 있나설명
kind항상"size_limit" · "unsupported" · "failed" · "arg" · "panic". 반환 코드와 짝이다(3·4·5·1·99). 파일이 없을 때는 코드가 2(NOT_FOUND)이고 kind 는 그 밖의 원인 그대로다.
message항상사람이 읽는 사유(한국어). 예: "지원하지 않는 포맷(감지=image)". 자체 파서가 이유 없이 못 읽은 경우 빈 문자열일 수 있다.
sizesize_limit파일 크기(바이트).
limitsize_limit걸린 상한(바이트).
text_kindsize_limittrue 면 텍스트·HTML 상한(max_file_bytes_text), false 면 일반 상한(max_file_bytes)에 걸렸다.
fmtunsupported감지된 형식 이름(예: "image"·"unknown").
layoutfailed · PDF(0.2.0~)PDF 파서가 쪽을 잰 뒤 실패했을 때(대개 사이냅 폴백에서 사이냅도 못 읽은 스캔 PDF) 성공 결과와 같은 모양의 쪽 구성. docparse_scan_pdf_verdict(pages, scan_pages, 0) 이 참이면 '실패'가 아니라 '처리제외(스캔 PDF)'로 다룬다. 감싸개: Python ExtractError.layout · Rust ExtractError::Failed{layout} · Java e.layout() · PHP $e->layout().

2-7. 압축 파일은 먼저 펼친다

docparse_extract 는 문서 한 개만 읽는다. zip·7z·rar·tar·gz 등은 docparse_expand 로 먼저 펼친다. 압축이 아닌 파일은 그대로 job 하나로 돌아오므로, 모든 입력을 expand 에 넘기고 나온 jobs[].src 마다 extract 하면 된다. 형식 감지(docparse_detect)는 압축 중 zip 만 "zip" 으로 알려 주고 7z·rar 등은 따로 알려 주지 않으므로, 감지 결과로 압축 여부를 가르지 않는다.

입력 [a.hwp, b.zip]
   └─ docparse_expand(["a.hwp","b.zip"], tmp_root, {"max_depth":3})
        → jobs = [ {src:"a.hwp",          label:"a.hwp",          origin:null},
                   {src:"<tmp>/a1",        label:"b.zip/안.docx",   origin:"b.zip"}, … ]
        → stats.unexpanded = 못 펼친 압축(암호·깨짐·상한)
   └─ jobs[].src 마다 docparse_extract
   └─ 다 쓰면 tmp_root 를 지운다 (펼친 파일이 tmp_root 바로 아래 a1, a2… 로 생긴다)
tmp_root

펼친 파일이 tmp_root 바로 아래에 생긴다. 공용 임시 폴더(%TEMP%, /tmp) 자체를 주지 말고 작업마다 새 폴더를 만들어 주고, 끝나면 지운다.

2-8. 스레드·로그

  • 전역 상태가 없어 여러 스레드에서 동시에 불러도 된다. 로거 등록만 프로세스 전체에 하나다.
  • 로그는 docparse_set_logger(fn, max_level, user) 로 받는다. level: 1=error 2=warn 3=info 4=debug 5=trace. 등록하지 않으면 버린다.
  • 콜백은 추출을 부른 스레드에서 불린다. 짧게 쓰고, 콜백 안에서 docparse 함수를 다시 부르지 않는다.
  • Python·Java·PHP 감싸개는 콜백 객체를 붙잡아 둔다. 직접 FFI 를 짤 때도 콜백이 GC 로 사라지지 않게 참조를 쥐고 있어야 한다.

2-9. 판 확인

불러온 직후 docparse_abi_version() == 1 인지 본다. 함수 모양이 바뀌면 이 숫자가 오르고, 감싸개는 숫자가 다르면 열지 않는다. docparse_version() 은 "0.1.0+b9704d2" 처럼 크레이트 판 + git 해시다. 로그에 함께 남겨 두면 나중에 어느 판이 만든 결과인지 알 수 있다.

Rust

Rust 쪽도 crate 로 링크하지 않고 실행 중에 DLL 을 연다(libloading). 그래서 파서만 새 판으로 바꿔 끼울 때 프로그램을 다시 빌드할 필요가 없다.

  1. 파일 두기 — rust/docparse_dyn.rs 를 src/ 에 복사하고 main.rs 에 mod docparse_dyn;.
  2. 의존 추가 — Cargo.toml 에 아래 두 줄.
  3. 라이브러리 두기 — lib/ 두 파일을 실행파일 옆(또는 한 단계 위)에 둔다. 아니면 환경변수로 알려 준다.
Cargo.toml[dependencies]
libloading = "0.8"
serde_json = "1"
src/main.rs (rust/example 과 같은 내용)mod docparse_dyn;
use docparse_dyn::{DocParse, ExtractError};
use serde_json::json;
use std::ffi::{c_char, c_int, c_void, CStr};
use std::path::{Path, PathBuf};

// 로그 콜백 — extern "C" fn 모양. msg 는 콜백이 도는 동안만 유효하다.
extern "C" fn on_log(level: c_int, _t: *const c_char, _s: *const c_char, msg: *const c_char, _u: *mut c_void) {
    eprintln!("[docparse {}] {}", level, unsafe { CStr::from_ptr(msg) }.to_string_lossy());
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // 찾는 순서: 직접 지정 → 환경변수 DOCPARSE_LIB → 실행파일 폴더 → 그 상위 폴더
    // 직접 지정(Some)했는데 없으면 다른 곳 것으로 대신하지 않고 실패한다.
    let dp = DocParse::find_and_load(None, "DOCPARSE_LIB")?;
    println!("docparse {} ({})", dp.version(), dp.path().display());
    dp.set_logger(Some(on_log), 2, std::ptr::null_mut());

    let tmp = std::env::temp_dir().join(format!("docparse-{}", std::process::id()));
    std::fs::create_dir_all(&tmp)?;
    let inputs = vec![PathBuf::from("a.hwp"), PathBuf::from("b.zip")];
    let ex = dp.expand(&inputs, &tmp, &json!({"max_depth": 3}))?;

    for (src, label, _origin) in &ex.jobs {
        let opts = json!({"clean": true, "label": label, "limits": {"max_pdf_pages": 500}});
        match dp.extract(src, &opts) {
            Ok(r) => println!("{} : {} {}자 partial={:?}", label, r.fmt, r.text.chars().count(), r.partial),
            Err(ExtractError::SizeLimit { size, limit, .. }) => println!("{} : 크기 초과 {} > {}", label, size, limit),
            Err(ExtractError::Unsupported { fmt, .. }) => println!("{} : 지원 안 함({})", label, fmt),
            Err(e) => println!("{} : {}", label, e),   // Failed · Arg · Panic
        }
    }
    println!("못 펼침: {:?}", ex.unexpanded);
    std::fs::remove_dir_all(&tmp)?;
    Ok(())
}

6-3. 코드

c/example.c (요약 — 전체판은 zip 펼치기 포함)#include <stdio.h>
#include <stdlib.h>
#include "docparse.h"
#ifdef _WIN32
#include <windows.h>
#include <shellapi.h>
/* [중요] Windows 의 argv 는 CP949 다. UTF-8 로 바꿔야 한글 경로가 된다. */
static char** utf8_argv(int* argc) {
    LPWSTR* w = CommandLineToArgvW(GetCommandLineW(), argc);
    char** a = calloc((size_t)*argc + 1, sizeof(char*));
    for (int i = 0; i < *argc; i++) {
        int n = WideCharToMultiByte(CP_UTF8, 0, w[i], -1, NULL, 0, NULL, NULL);
        a[i] = malloc((size_t)n);
        WideCharToMultiByte(CP_UTF8, 0, w[i], -1, a[i], n, NULL, NULL);
    }
    LocalFree(w);
    return a;
}
#endif

static void on_log(int level, const char* target, const char* site, const char* msg, void* user) {
    fprintf(stderr, "[docparse %d] %s\n", level, msg);
}

int main(int argc, char** argv) {
#ifdef _WIN32
    argv = utf8_argv(&argc);
    SetConsoleOutputCP(CP_UTF8);
#endif
    if (docparse_abi_version() != DOCPARSE_ABI_VERSION) return 1;   /* 판이 다르면 쓰지 않는다 */
    printf("docparse %s\n", docparse_version());                    /* 고정 문자열 — 해제하지 않음 */
    docparse_set_logger(on_log, 2, NULL);

    for (int i = 1; i < argc; i++) {
        char* out = NULL;
        int code = docparse_extract(argv[i], "{\"clean\":true,\"limits\":{\"max_pdf_pages\":500}}", &out);
        switch (code) {
        case DP_OK:             printf("성공: %.200s\n", out); break;   /* {"text":…,"fmt":…} */
        case DP_ERR_SIZE_LIMIT: printf("크기 초과: %s\n", out); break;
        case DP_ERR_NOT_FOUND:  printf("파일 없음: %s\n", argv[i]); break;
        default:                printf("실패(%d): %s\n", code, out); break; /* {"error":{…}} */
        }
        docparse_free(out);      /* 성공이든 실패든 반드시. NULL 이어도 된다 */
    }
    docparse_set_logger(NULL, 0, NULL);
    return 0;
}

결과가 JSON 이므로 실제 프로그램에서는 cJSON·jansson(C), nlohmann/json(C++) 등으로 읽는다. C++ 에서는 extern "C" 가 헤더에 이미 들어 있어 그대로 #include 하면 된다. 해제를 잊지 않으려면 std::unique_ptr<char, decltype(&docparse_free)> p(out, docparse_free); 처럼 감싸 두면 편하다.

#endif
typedef int  (*extract_fn)(const char*, const char*, char**);
typedef void (*free_fn)(char*);
extract_fn dp_extract = (extract_fn)SYM("docparse_extract");

Java

JNA 로 감쌌다. JNI 처럼 C 코드를 따로 짜거나 컴파일할 필요가 없고 Java 8 부터 쓸 수 있다. 결과를 바로 쓸 수 있게 외부 라이브러리 없는 작은 JSON 해석기(docparse.Json)를 함께 넣었다.

  1. 의존 추가 — JNA 하나. jar 안에 Windows·Linux 용 네이티브 조각이 들어 있다.
  2. 소스 두기 — java/docparse/ 폴더(DocParse.java·Json.java)를 소스 트리에 docparse 패키지로 복사한다. 패키지 이름을 바꾸려면 두 파일의 package 줄을 고친다.
  3. 라이브러리 두기 — 작업 폴더 lib/ 에 두거나 -Ddocparse.lib=/opt/app/lib/libdocparse.so, 환경변수 DOCPARSE_LIB 로 알려 준다.

Example.java (요약 — Java 8 이상, 묶음의 Example.java 도 같은 흐름)import docparse.DocParse;
import java.io.File;
import java.util.*;

public class Example {
    public static void main(String[] args) {
        DocParse dp = DocParse.load();          // 또는 DocParse.load("C:/app/lib/docparse.dll")
        System.out.println(dp.version() + " " + dp.libPath());

        // 로그 — 콜백은 추출을 부른 스레드에서 불린다
        dp.setLogger((level, target, site, msg) -> System.err.println("[docparse " + level + "] " + msg), 2);

        // 1) 한 파일
        DocParse.Extracted r = dp.extract("보고서.hwp", "{\"clean\":true,\"limits\":{\"max_pdf_pages\":500}}");
        System.out.println(r.fmt + " " + r.text.length() + " partial=" + r.partial + " layout=" + r.layout);

        // 2) 압축 포함 여러 파일
        File tmp = new File(System.getProperty("java.io.tmpdir"), "docparse-" + System.nanoTime());
        tmp.mkdirs();
        Map<String, Object> ex = dp.expand(Arrays.asList("a.hwp", "b.zip"), tmp.getPath(), "{\"max_depth\":3}");
        @SuppressWarnings("unchecked")
        List<Map<String, Object>> jobs = (List<Map<String, Object>>) ex.get("jobs");
        for (Map<String, Object> j : jobs) {
            String src = (String) j.get("src"), label = (String) j.get("label");
            try {
                DocParse.Extracted x = dp.extract(src, "{\"clean\":true,\"label\":" + docparse.Json.quote(label) + "}");
                System.out.println(label + " : " + x.fmt + " " + x.text.length());
            } catch (DocParse.SizeLimitException e) {          // 크기 상한 → 처리 제외
                System.out.println(label + " : 크기 초과 " + e.size + " > " + e.limit);
            } catch (DocParse.DocParseException e) {           // e.kind: not_found·unsupported·failed·arg·panic
                System.out.println(label + " : " + e.kind + " — " + e.getMessage());
            }
        }
        // 다 쓰면 tmp 폴더를 지운다
    }
}

시험 상태

이 문서를 쓸 때 PHP 실행 환경을 쓸 수 없어 PHP 감싸개는 실행 시험을 하지 못했다. 코드는 PHP FFI 문서의 규칙(cdef 선언·FFI::addr·FFI::string·FFI::isNull)대로 작성했고 함수 모양은 C·Java 시험과 같다. 처음 쓸 때 묶음의 example.php 를 한 번 돌려 확인하기를 권한다.

  1. FFI 켜기 — PHP 7.4 이상, php.ini 에 extension=ffi(Windows 는 ext/php_ffi.dll). 확인: php -m | grep FFI.
  2. CLI 와 웹은 설정이 다르다 — 기본값 ffi.enable=preload 에서는 CLI 에서만 바로 된다. php-fpm·Apache 모듈에서 쓰려면 ffi.enable=true 로 두거나 opcache.preload 로 미리 불러야 한다.
  3. 파일 두기 — php/DocParse.php 를 프로젝트에 복사하고 require. 라이브러리는 실행 폴더 lib/, DocParse.php 옆이나 그 lib/, 또는 DOCPARSE_LIB.
php.iniextension=ffi
; 웹 서버(php-fpm·Apache)에서 쓸 때만
ffi.enable=true

그 밖의 언어

C 함수 11개와 JSON 문자열만 다루면 되므로 FFI 가 있는 언어는 모두 같은 방식이다. 감싸개를 새로 만들 때는 이 순서만 지키면 된다.

  1. 라이브러리를 열고 docparse_abi_version() == 1 확인
  2. 문자열 인자는 UTF-8 바이트로 넘기기(그 언어의 기본 마샬링이 시스템 코드페이지면 바꾸기)
  3. char** 결과는 포인터로 받아 UTF-8 로 읽고 곧바로 docparse_free
  4. 반환 코드 0 이 아니면 결과 JSON 의 error 로 예외 만들기, 3 은 크기 초과로 따로
  5. 로그 콜백을 등록했다면 콜백 객체가 GC 되지 않게 붙잡아 두기
