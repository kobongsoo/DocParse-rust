PDF 페이지 구성 보존(A · B)과 본문 밖 글 읽기(C)

사이냅 폴백 모드에서 스캔 PDF 의 페이지 구성(layout)이 사라져 처리제외 판정이 빠지는 문제(A · B)를 고치고, 사이냅은 읽는데 docparse 는 읽지 않던 본문 밖 글(PDF 글상자 주석 · PDF 서식 칸 값 · Word 메모 · SmartArt)을 기본으로 읽게 한다(C). 고칠 곳은 이 저장소의 crates\docparse · crates\docparse-ffi · 감싸개 4종이고, 결과를 쓰는 MpowerClassify 쪽 후속은 9장에 따로 적는다.

개정 1(2026-11-18) — C 를 'PDF 주석 읽기 · 기본 끔'에서 '본문 밖 글 읽기 · 기본 켬'으로 넓혔다. 근거: 이 PC 의 사이냅(snf_exe 4.29.0)과 직접 비교한 결과(5장).
개정 2(2026-11-18) — 숨김 표시가 있는 PDF 글상자도 사이냅처럼 읽는다(6장 · 11장).

요약
  • A — 사이냅으로 넘어갈 때 '부분 추출' 표식만 지우고 layout 은 남긴다. Python 판 notes.py 와 같은 규칙. 사이냅이 이기거나 짧은 결과를 채택한 문서에도 layout 이 붙는다.
  • B — 모든 엔진이 실패해도 PDF 파서가 잰 layout 을 오류에 싣는다(오류 JSON 에 "layout" 키 추가). 1.pdf 처럼 사이냅도 못 읽은 스캔 PDF 를 부른 쪽이 처리제외로 가를 수 있다.
  • C — 사이냅이 읽는 본문 밖 글을 docparse 도 기본으로 읽는다: PDF 글상자(FreeText) 주석 · PDF 서식 칸 값 · docx 메모 · pptx/docx SmartArt. 옵션 "extra_text": false 로 끌 수 있다. 숨긴 PDF 글상자도 사이냅처럼 읽는다(개정 2). 사이냅과 다르게 두는 것은 pptx 발표자 노트(우리만 읽음 → 그대로 읽음) 하나.
  • A · B 는 본문(text)을 바꾸지 않는다 — 결과 바뀜 없음(layout 이 더 붙을 뿐). C 는 결과 바뀜 — 본문 밖 글이 든 문서의 본문이 늘어난다. 그래서 0.2.0.
  • C ABI 는 그대로(ABI 1) — 새 JSON 키로만 더한다. Rust 크레이트 API 는 ExtractError::Failed 모양 · ExtractOptions 칸이 바뀐다.

MpowerClassify 작업 세션에서 보고된 내용(2026-11-18):

  • Rust 판(MpowerClassify-rs)을 --synap-fallback 으로 돌리면, 사이냅이 이긴 문서에서 페이지 정보가 사라져 처리제외 표시가 빠진다.
  • D:\sample\scanpdf\1.pdf 는 처리제외가 아니라 extract_failed 가 된다.
  • dp.exe 로 직접 돌려도 layout: null 이 나온다 → MpowerClassify 가 아니라 docparse 에서 고칠 일.

2원인 (A · B)

A — 사이냅 차례에서 표식을 통째로 지운다

crates\docparse\src\extract.rs 의 extract_as 사이냅 폴백 루프:

지금 코드(요점)
// 마지막으로 시도한 엔진이 남긴 표식 — 분리 전에는 엔진마다 메모를 비웠으므로,
// 결과에 붙는 표식은 언제나 '마지막에 돈 엔진'의 것이었다. 그 규칙을 그대로 지킨다.
let mut notes: (Option<Partial>, Option<Layout>) = (None, None);
for name in engines {
    let got = if name == "snf" {
        notes = (None, None);                       // ← partial 과 함께 layout 도 지움
        crate::synap::snf_extract(snf, path, snf_secs)
    } else {
        let run = Run::new(opts);
        let r = extract_raw(path, fmt, &run)…;
        notes = run.into_notes();
        r
    };
    …

주석이 말하는 '분리 전 규칙'은 partial 에만 맞다. Python 판은 두 표식을 일부러 다르게 다룬다:

표식Python 판(MpowerClassify extract/notes.py · hybrid.py)Rust docparse 지금
partial (부분 추출)엔진마다 notes.reset() 으로 비움 — 1차 파서의 "일부만 읽음"이 사이냅 결과에 붙지 않게같음 맞음
layout (페이지 구성)reset() 이 건드리지 않는다. 문서마다 reset_layout() 한 번만. 주석: "pdfium 이 짧은 결과를 내고 사이냅으로 넘어가면, reset() 이 pdfium 이 잰 페이지 구성까지 지워 스캔본을 못 가린다"사이냅 차례에 지움 다름

B — 실패에는 layout 을 실을 자리가 없다

  • 스캔 PDF 는 pdfium 결과가 빈 문자열이라 하이브리드가 짧은 결과로도 못 붙잡고 → 사이냅도 비거나 실패 → Err(ExtractError::Failed(String)).
  • ExtractError::Failed 는 문자열 하나뿐이고, C 진입점의 오류 JSON {"error":{"kind","message"}} 에도 layout 자리가 없다.
  • Python 판은 이 갈래를 따로 다룬다 — cli.py 의 except ExtractError 에서 notes.take_layout() 로 남은 layout 을 꺼내 _scan_pdf_excluded(layout, 0) 이면 처리제외. 주석: "스캔 PDF 는 대개 이 갈래로 온다 … 실측: 사이냅도 0바이트".
  • 기본 엔진(builtin)은 스캔 PDF 를 Ok("") + layout 으로 돌려주므로 이 문제가 없었다. 사이냅 모드에서만 드러난다.

3설계 A — 사이냅으로 넘어가도 layout 유지

사이냅 차례에서 partial 만 비운다. layout 은 PDF 파서(자체 파서)가 잰 값이 그대로 남아 어느 엔진의 결과에든 붙는다.

바뀐 코드(안)
// partial 은 '그 결과를 낸 엔진'의 것이어야 하고(사이냅 전문에 1차의 '일부만'이 붙지 않게),
// layout 은 '문서'의 것이다 — 사이냅은 쪽 구성을 재지 않으므로 PDF 파서가 잰 값을 끝까지 둔다
// (Python 판 notes.reset() / reset_layout() 와 같은 나눔).
let mut partial: Option<Partial> = None;
let mut layout: Option<Layout> = None;
for name in engines {
    let got = if name == "snf" {
        partial = None;                            // layout 은 그대로
        crate::synap::snf_extract(snf, path, snf_secs)
    } else {
        let run = Run::new(opts);
        let r = extract_raw(path, fmt, &run)…;
        let (p, l) = run.into_notes();
        partial = p;
        layout = l;
        r
    };
    …
    return Ok(Extracted { …, partial, layout });

사이냅이 이긴 문서에 layout 이 붙으면, 부른 쪽은 사이냅이 읽은 본문 길이와 layout 으로 판정한다(scan_pdf_verdict(pages, scan_pages, body_chars)). 사이냅이 쪽마다 10자 이상을 읽었다면 처리제외가 아니다 — Python 판과 같은 결론이다.
그대로 두는 것 — 둘 다 짧아 pdf 결과를 채택해도 partial 은 마지막에 돈 snf 의 것(없음)이 된다. Python 판도 같으므로 이번에는 바꾸지 않는다(바꾸면 두 판이 갈린다). synap_only 에서 PDF 의 layout 을 따로 재는 일도 이번 범위 밖이다.

4설계 B — 실패에도 layout 싣기

Rust 크레이트(docparse)

ExtractError 바뀐 모양(안)
pub enum ExtractError {
    SizeLimit { size: u64, limit: u64, text_kind: bool },
    Unsupported(Fmt),
    /// 읽지 못함. reason 은 사람이 읽는 사유(자체 파서 단독이면 빈 문자열 — 지금과 같음).
    /// layout 은 PDF 파서가 쪽을 재고 나서 실패했을 때만 있다(스캔 PDF 처리제외 판정 재료).
    Failed { reason: String, layout: Option<Layout> },
}
  • 사이냅 폴백의 '전엔진 실패' — 루프가 가진 layout(A 에서 남긴 값)을 싣는다.
  • 사이냅만 모드 실패 · 자체 파서 단독 실패(extract_builtin 의 None) — layout 은 None(지금과 같은 뜻). 자체 파서 단독은 PDF 를 열지 못한 경우라 잰 쪽이 없다.
  • Display 는 reason 만 쓴다 — 사람용 문장은 지금과 같다.
  • 모양이 바뀌므로 크레이트를 직접 쓰는 곳(docparse-ffi · docparse-cli, 이 저장소뿐)을 함께 고친다. 0.x 라 부 버전에서 바꿔도 된다.
다른 안과 견줌 — ① 전엔진 실패라도 PDF 파서가 빈 결과 + layout 을 냈으면 Ok("") 로 돌려주는 안(기본 엔진과 같은 모양): 부른 쪽은 안 고쳐도 되지만, 스캔이 아닌 빈 PDF 까지 '실패 → 본문 없음 성공'으로 바뀌어 종료코드 · 실패 집계가 달라진다. ② Failed 는 두고 새 변형을 더하는 안: match 하는 쪽이 새 변형을 빠뜨리기 쉽다. → 오류에 layout 을 싣는 안을 고른다. Python 판(실패 갈래에서 layout 으로 판정)과 같은 모양이고, 실패는 실패로 남는다.

C 진입점(docparse-ffi) — 오류 JSON

실패 결과 JSON (layout 은 있을 때만)
{ "error": { "kind": "failed",
             "message": "하이브리드 전엔진 실패(감지=pdf; pdf:empty; snf:…)",
             "layout": { "pages": 2, "scan_pages": 2 } } }
  • docparse.h 머리 주석의 '추출 결과 JSON' 설명에 "layout" 을 더한다. 함수 모양 · 상태 코드는 그대로 → ABI 1 유지(버전 규칙: 새 기능은 새 JSON 키로).
  • 상태 코드는 그대로 DP_ERR_FAILED(5) — 실패는 실패다. 처리제외로 가를지는 부른 쪽이 정한다.

dp.exe

  • 실패 줄에 layout 과 판정을 붙인다: 실패(5 DP_ERR_FAILED): 하이브리드 전엔진 실패(…) layout={"pages":2,"scan_pages":2} 판정=스캔PDF(처리제외) — 본문 0자로 docparse_scan_pdf_verdict 를 부른다(Python 판 실패 갈래와 같은 식).
  • dump 의 index.json 실패 줄에도 layout 을 남긴다. compare 는 layout 을 비교하지 않는다(지금처럼 rc · fmt · engine · 본문).

판정이 갈린 과정

  1. Python 판: 자체 파서가 3자만 읽자 기본 동작대로 사이냅으로 다시 읽어 주석 글을 얻었다.
  2. 그 글의 "국정원 산업기밀보호센터" 속 "기밀"이 '기밀 표식' · '대외비/기밀 스탬프' 두 규칙에 걸려 등급 C.
  3. 그런데 이 "기밀"은 피해 통계의 출처 기관 이름이지 문서가 기밀이라는 표시가 아니다 → 오탐에 가깝다.
  4. Rust 판: 사이냅을 쓰지 않아 3자 → 처리제외.
주석 글을 읽어도 2.pdf 는 scan_pdf_verdict 기준으로 여전히 스캔 PDF 다 — 본문 3+103 = 106자 ÷ 33쪽 ≈ 3.2자/쪽 < 10자/쪽, 스캔 쪽 32/33. Python 판이 처리제외와 별개로 등급 C 를 낸 것은 분류 쪽 순서(등급 판정과 처리제외 표식이 함께 붙는 구조)로 보인다 — MpowerClassify 쪽에서 확인할 일(9장).

  • 기본 켬 — 사이냅과 다르게 읽히던 것을 맞추는 것이 목적이다. 끄는 값은 0.1.x 결과와 견주거나(평가셋 재현) 문제가 생겼을 때 되돌리는 용도다.

  • 사이냅 폴백과의 관계: 자체 파서가 본문 밖 글까지 읽으면 짧은 결과가 줄어, 사이냅으로 넘어가는 문서가 줄 수 있다(같은 글을 사이냅 없이 얻는다).

스캔 판정과의 관계

  • pdf_is_scan_page(쪽 단위 판정)는 쪽 본문 글자만 본다 — 주석 · 서식 칸은 쪽 위에 덧붙인 것이라, 그림이 쪽을 덮은 스캔 쪽인지를 바꾸면 안 된다. scan_pages 는 옵션과 무관하게 같다.
  • scan_pdf_verdict 의 본문 길이는 부른 쪽이 최종 본문으로 센다 → 주석 글만큼 늘어난다. 쪽당 10자 기준이라 주석 몇 줄로는 잘 뒤집히지 않는다(2.pdf: 3.2자/쪽 → 여전히 스캔 PDF).

한계

  • /Contents 가 비고 겉모양(appearance)에만 글이 그려진 글상자는 못 읽는다 — 겉모양 글 추출은 pdfium 공개 API 로 쉽지 않다. 2.pdf 8개는 모두 /Contents 가 있다.
  • SmartArt 는 dataN.xml 의 점(pt) 차례대로 읽는다 — 화면에 그려진 차례와 다를 수 있다(사이냅의 차례도 확인 대상).
  • hwp · hwpx 메모 · docx 각주/미주는 이번 범위 밖 — 샘플로 사이냅과 비교한 뒤 정한다(11장).
다른 안 — ① 기본 끔(개정 전 안): 0.1.x 결과를 지키지만 사이냅과의 차이가 그대로 남는다 — 사이냅을 안 쓰는 Rust 판과 쓰는 Python 판이 계속 갈린다. ② 본문에 섞지 않고 결과 JSON 에 "extra": [{"kind","page","text"}] 로 따로 주기: 본문이 안 바뀌지만 감싸개 · 분류 쪽까지 새 필드를 다뤄야 쓸 수 있고, 사이냅(본문에 섞음)과 모양이 다르다. → 본문에 붙이고 기본 켬을 고른다.
오탐은 규칙 쪽 일 — 본문 밖 글이 늘면 2.pdf 의 "국정원 산업기밀보호센터" 같은 출처 문구가 규칙에 걸릴 수 있다. 기관 이름 속 "기밀"을 기밀 표식에서 빼는 일은 MpowerClassify 규칙(ruleset)에서 다룬다. docparse 는 문서에 있는 글을 읽을 뿐 걸러내지 않는다.
